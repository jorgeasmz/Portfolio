## A Forecast Is Only Worth Its Baseline

Any model produces a line on a chart. The question is whether that line beats the cheapest
possible alternative, and for a seasonal series the cheapest alternative is not "repeat the last
value" but "repeat what happened this month last year".

Backtested on monthly car sales with the final twelve months held out:

| Model | MAPE | MAE | RMSE |
|---|---|---|---|
| **Prophet** | **7.19%** | **1336.8** | **1749.2** |
| Seasonal naive (t−12) | 10.83% | 1959.5 | 2290.8 |
| Naive (last value) | 22.27% | 4599.0 | 5865.4 |

Prophet cuts the error of the seasonal baseline by a third. Beating the last-value baseline would
have proved nothing on a series with this much annual structure; the seasonal one is the bar that
had to be cleared.

## The Test That Found a Live Bug

The chart on the deployed app had been broken, and nobody had noticed because the failure only
triggers after training completes.

Prophet's own Plotly helper runs `assert m.history` on a pandas DataFrame. Pandas refuses to
evaluate a DataFrame's truthiness and raises `ValueError` instead, so the assertion fails for
every fitted model, which is the only kind you would ever plot. The intent was clearly to check
that the model had been trained; the effect was the opposite.

The figure is now built directly with `graph_objects`: observed points, the prediction line and
the uncertainty band as a filled region. That removed the dependency on a broken helper and made
the chart consistent with the rest of the visualisations.

The test that caught it was a smoke test, the kind that is easy to skip on the grounds that
plotting code is not worth covering.

## Architecture

Each stage is a module with a single responsibility, and data access is split in two: a pure
function that reads and raises, and a cached Streamlit wrapper that catches and degrades to an
empty frame. The application needs to show a warning rather than a traceback; the tests need a
failure to be observable. One function cannot do both.

## Engineering Notes

so the fast suite stays under a second. The evaluation itself is a committed script rather than
