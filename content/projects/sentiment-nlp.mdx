## Serving a Transformer Is the Easy Half

Wrapping a Hugging Face pipeline in an API takes an afternoon. The interesting question is what
the model does when the input is not a movie review, and whether its own confidence tells you
anything about that.

So the evaluation is not a single accuracy number. It is a curated set of 29 cases grouped by
the linguistic phenomenon each one probes.

| Category | Accuracy |
|---|---|
| Clear positive | 100% |
| Clear negative | 100% |
| Mixed sentiment | 100% |
| Negation | 67% |
| Short phrases | 75% |
| **Sarcasm** | **33%** |
| **Overall** | **82.8%** |

## The Confidence Score Is Not a Trust Signal

The failures are not sitting near the decision boundary where you might catch them. They come
back at the top of the range:

| Text | Expected | Predicted | Score |
|---|---|---|---|
| Oh brilliant, another update that breaks everything. | NEGATIVE | POSITIVE | 1.00 |
| Wonderful, it arrived in three pieces. Exactly what I wanted. | NEGATIVE | POSITIVE | 1.00 |
| Never again. | NEGATIVE | POSITIVE | 0.99 |

A sentence-level classifier reads surface lexical cues. Sarcasm inverts the meaning while leaving
those cues intact, so the model is not merely wrong, it is **confidently** wrong.

The practical consequence matters more than the observation: filtering predictions by confidence
would keep exactly the wrong ones. Any deployment on user-generated text needs a different
design, not a higher threshold. That is the sort of conclusion an evaluation is for.

## Architecture

Three layers with one responsibility each. `core` owns the model, `api` owns HTTP, `web` owns
presentation, and the client reaches the service over HTTP only, which is what allows the two
halves to be deployed independently: the API runs as a Docker Space on Hugging Face, the client
on Streamlit Cloud.

The model loader is a **lock-guarded singleton**. FastAPI serves synchronous endpoints from a
worker threadpool, so without the lock two concurrent first requests could each start loading a
250 MB checkpoint.

## Engineering Notes

Latency is measured, not assumed: 36.6 ms mean and 46.8 ms p95 for single-item CPU inference.

One fix is worth recording because it is invisible until you look. `requirements.txt` pinned
torch through `torch --index-url .../cpu`, and that option is a global directive in a
requirements file. Appended to a package it is ignored, so pip resolved torch from PyPI and
installed the CUDA build: a 4 GB environment of NVIDIA libraries for a service that runs on CPU.
Declared correctly, the same install is 1.5 GB.
